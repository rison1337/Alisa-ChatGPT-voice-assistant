WINDOWS: ИСПРАВЛЕН КОД РЕЗУЛЬТАТА ОБНОВЛЕНИЯ
30.10.2026, локальная 0.3.0.dev1, без публикации

Это дополнение к 05-UPDATER-WINDOWS-RESULTS.txt. Ранее открытая потеря
exit code исправлена. Прежние результаты и границы проверки не отменяются.

ПРОБЛЕМА И ПРИЧИНА
Прежний alisa.cmd ждал установленный python.exe. При os.execv в Windows
старый процесс завершался с 0, а отдельный worker продолжал обновление.
CMD получала результат старого процесса. Поэтому даже rolled_back и
recovery_needed выглядели успешными для вызывающей программы.
Вторая такая граница была в повторном открытии CLI после работы worker.

ИСПРАВЛЕНИЕ
1. Windows installer ставит управляющий launcher и отдельную копию embedded
   Python вне заменяемой папки app. У этой копии изолированный ._pth;
   launcher не импортирует модули приложения и не держит его DLL открытыми.
2. alisa.cmd ждёт этот процесс и явно возвращает его exit code.
3. CLI передаёт проверенное задание через отдельный приватный JSON на один
   запуск и завершается внутренним служебным кодом. Launcher дожидается
   освобождения CLI, запускает настоящий worker и возвращает его результат.
   Внешнему вызывающему коду служебный код не выдаётся.
4. При интерактивном обновлении launcher вновь открывает CLI после выхода
   worker; успешный выход из меню сохраняет предыдущий код ошибки обновления.
   Возможны повторные обновления в том же окне. Worker на Windows также
   сохраняет ошибку при собственном повторном запуске CLI.
5. Обычная установка с запуском CLI использует тот же механизм. Прямое
   python alisa.py update в Windows отказывает до изменений и предлагает
   установленный alisa.cmd. Linux-передача через execv сохранена.
6. Runtime launcher хранится в каталоге по хешу. Совпадающие файлы не
   переписываются, изменённые и неизвестные файлы сохраняются; при изменении
   собственных файлов создаётся отдельная копия. Пользовательский state,
   аккаунты, чаты, SSH, VPN и app.previous* не очищаются.

РЕЗУЛЬТАТ ДЛЯ КОМАНДЫ
complete -> 0; rolled_back -> 1; recovery_needed -> 1.
Обычные команды сохраняют собственный код завершения.
update-status.json сохраняет подробную фазу и результат восстановления.
Для перехода требуется один запуск исправленного установщика и новый CLI:
уже запущенная старая команда не может получить новый способ ожидания задним
числом. На проверяемой Windows исправленная итоговая версия уже установлена.

ПОВТОРНЫЕ ПРОВЕРКИ
На прежнем коде новый регрессионный тест воспроизвёл три неверных результата
CMD: версия не совпала, ошибка компонентов, неполное восстановление.
После исправления тот же настоящий alisa.cmd и Windows worker возвращают
правильные коды. В этом автоматическом тесте станцию имитируют файлы.
Дополнительно проверены: повторное открытие меню после ошибки; сохранение
данных и app.previous*; обычный код 7; кириллица, пробелы и кавычки; изменённый
launcher и посторонний файл; отказ прямого Python до изменения приложения.

Отдельно выполнен полный установленный CLI с настоящим ZIP+SHA:
успешная замена приложения -> complete/0; неверная версия -> rolled_back/1;
внешняя Windows-блокировка папки -> rolled_back/1. Синтетический state,
SSH/profile, неизвестные файлы и резервные копии сохранены. Очистка временного
payload и отложенное удаление занятой DLL повторно проверены.
Настоящий интерактивный терминал: после успешного обновления и после отката
CLI снова открылся в том же окне; после выхода вернулись соответственно 0/1.

Живая Лайт 2: реальный неудачный кандидат вернул rolled_back/1 и восстановил
native; успешный кандидат вернул complete/0. Аккаунт, чаты, фразы, настройки,
SSH и исходные флаги сохранены, автоматического GPT-вызова не было. Сеть и
SSH-служба станции в этом дополнительном прогоне не менялись.
Итоговый Windows app возвращён с синтетической dev2 на исправленную dev1.
Колонка установлена, подключена и в idle; исходные VPN/автозапуски сохранены.

Итоговая сборка: 29 Windows host + 17 updater + 64 переносимых + 10
дополнительных = 120 passed, один Linux worker skip. 11 Linux/mock-случаев
по-прежнему исключены из переносимой выборки с явными причинами.
Проверены START-WINDOWS.cmd --check-only, manifest, ZIP SHA-256 и суммы
переданных файлов после записи на флешку. Подробные логи — evidence/exit-code-fix/.

Лайт 1/mute GPIO и Windows-мост не подтверждаются. Новый публичный GitHub
release не создавался. Повторной проверки старого браузерного входа и VPN
не потребовалось: их сохранённые данные не заменялись. КВМ/диски не трогались.
Ключи, profiles/state, закрытые checkpoint, подписки и локальные исследования
в поставку не включены. Рабочие тестовые dev2/dev3 в поставку не входят.
