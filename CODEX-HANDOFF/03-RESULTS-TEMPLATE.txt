БРАУЗЕРНЫЙ ВХОД: ЧТО ИМЕННО ИСПРАВЛЕНО И ПРОВЕРЕНО
1. Edge держит live Cookies SQLite заблокированной. После чтения SQLite
   соединение теперь действительно закрывается; при блокировке Windows
   watcher ищет меню профиля через UIAutomation только в собственном PID.
2. Обычное окно и импорт отключают расширения/синхронизацию, используют
   одинаковый обычный Windows User-Agent. HeadlessChrome UA приводил
   к Cloudflare 403 в реальном импорте. Окно развёрнуто для меню профиля.
3. Cookies chatgpt.com и .chatgpt.com содержали старые/обновлённые части.
   Выбор плоским dict смешивал части и давал login_required на колонке.
   Теперь выбирается целый набор одной семьи/домена/пути, без склейки
   между доменами; канонический .chatgpt.com имеет приоритет.
4. Отмена/ошибка закрывает только собственное окно, оставляет прежний вход;
   кандидат проверяется на колонке ДО замены действующей сессии.
5. Финальная реальная цепочка native login: обычный Edge -> автоматическое
   обнаружение -> headless import -> refresh на колонке -> сохранение.
   Всё прошло, account_id совпал, старые chat IDs/selected сохранены;
   собственный браузер закрыт, DevToolsActivePort удалён.
6. Это ПОВТОРНЫЙ вход того же аккаунта: отдельный тестовый профиль заранее
   получил существующую сессию владельца. Обычному окну помогли активацией
   и Reload. Чистый первый вход с вводом логина/пароля, MFA, CAPTCHA,
   новые условия Voice и полностью самостоятельный сценарий не проверены.
