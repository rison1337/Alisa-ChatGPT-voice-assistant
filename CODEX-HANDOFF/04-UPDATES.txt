ЛОКАЛЬНЫЙ ПАКЕТ ДЛЯ SELF-UPDATE
Публичного релиза с этим updater пока нет. Не выпускать его ради проверки.
Сначала использовать отдельный тестовый LOCALAPPDATA и ALISA_HOME,
синтетические данные вместо реальных аккаунтов, уникальную новую папку.
Не менять HOME, не подставлять реальный state в тестовую копию.

Создать отдельную копию исходников пакета, задать ей следующую версию,
например 0.3.0.dev2 в alisa_cli/__init__.py, собрать ZIP:
  windows\runtime\python.exe -B -X utf8 scripts/bundle_windows.py --output build\candidate-new --archive
Из старого установленного app запустить его alisa.cmd:
  update --archive <полный путь к ZIP> --version 0.3.0.dev2 --yes
Рядом с ZIP обязателен .sha256, версия manifest должна совпасть.
Источник под Git или непредусмотренная папка app не заменяются updater.

    app.previous*, изменённые/посторонние файлы и state остаются.

РЕАЛЬНАЯ КОЛОНКА — ПОСЛЕ ИЗОЛИРОВАННОГО ЦИКЛА
[ ] При активном разговоре обновление отклоняется до замены компонентов.
[ ] Idle + доступный SSH: обновляются клиент и модули, аккаунт/чаты/фразы/
    подсветка/VPN-конфиг/автозапуск сохраняются. Сам GPT-тест не включается.
[ ] Ранее выключенный режим сам не стартует; ранее работавший возвращается.
[ ] При недоступности SSH ошибка и откат описываются честно; неполное
    восстановление отображается как recovery_needed, не как успех.
Не запускать долгие/звуковые проверки без учёта текущей работы владельца.

Результаты записать отдельно с ОС, браузером, версией и сценариями. Не
включать токены, VPN-ссылки, profiles, state и SSH-ключи в возвращаемые файлы.
Публикация/merge/release остаются запрещены до команды пользователя.
