НАСТОЯЩИЙ WINDOWS-ТЕРМИНАЛ И МЕНЮ
Проверены «Не сейчас» и «Больше не спрашивать». Первое оставляет предложения;
второе выключает их сетевую проверку. Настройка сохраняется в новом процессе.

Ручная проверка доступна при выключенных предложениях и после перезапуска.

а новая CLI появляется в том же терминале после замены приложения.
Только транспорт release metadata/загрузки в TUI направлен на локальный
fixture; выбор, проверка ZIP, self-exec, worker и перезапуск настоящие.
Контролируемый сетевой отказ GitHub не блокирует CLI: запуск завершился
за 2.897 с; ручная проверка выдаёт понятную ошибку без Traceback.

ОТКРЫТОЕ ОГРАНИЧЕНИЕ
Windows alisa.cmd после self-exec возвращал 0 также при rolled_back и
recovery_needed. Сообщение и update-status.json содержат правильный исход;
при прямом запуске worker ошибка даёт ненулевой код. Передача кода через
Windows launcher/self-exec не исправлена этим пакетом. Автоматизация должна
проверять phase в update-status.json, а не принимать один exit code за успех.
Обычный preflight-отказ до self-exec возвращает 1 корректно.
