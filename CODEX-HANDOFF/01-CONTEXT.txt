АРХИТЕКТУРА
START-WINDOWS.cmd -> windows/install.py -> alisa.py -> alisa_cli/cli.py.
windows/install.py проверяет windows-package.json, копирует программу
в %LOCALAPPDATA%\AlisaVoice\app и запускает CLI. Изменений колонки на этом
этапе нет. Настройки отдельно: %LOCALAPPDATA%\AlisaVoice\state.
Повторная установка с тем же содержимым не копирует программу заново.
Обновление заменяет app с резервной копией, не трогая state. Прежние копии
app.previous и app.previous-<время> сохраняются; сами не удаляются.
Неизвестная папка app без нашего маркера не перезаписывается.

alisa_cli/windows.py — Chrome/Edge, UTF-8/ANSI, права папки текущего Windows
пользователя через Win32 DACL. Хранилище должно быть на локальном NTFS.
alisa_cli/winssh.py — Paramiko вместо внешних ssh/ssh-keyscan/ssh-keygen.
Первое подключение подтверждает отпечаток хоста, смена ключа отклоняется.
Пароль только в памяти. Создаётся отдельный ed25519-ключ установщика;
прежний authorized_keys сохраняется. После проверки ключа данные записываются.
Station в alisa_cli/ssh.py выбирает Windows-транспорт, остальной код общий.
Stream нужен для живого демо LED; Forward — локальный канал к SOCKS колонки.

alisa_cli/win_browser.py — отдельный профиль Chrome/Edge для входа.
Обычное окно входа запускается без remote-debugging и automation-флагов.
alisa_cli/login_browser.py наблюдает за сессионными cookies SQLite.
После обнаружения входа окно закрывается; короткий headless-запуск
с локальным случайным DevTools-портом читает сессию в том же профиле.
alisa_cli/accounts.py проверяет новую сессию на колонке до замены старой.
При VLESS браузер входа использует SSH-туннель к SOCKS на колонке.
Не закрывать личный браузер пользователя и не печатать cookies/токены.

alisa_cli/vpn.py выбирает Windows x64 валидатор Xray/sing-box для проверки
конфигурации, на колонку ставится ARM-ядро. Туннель только для GPT;
при отказе VPN нельзя молча переходить на прямое соединение.
Native-автозапуск — на самой колонке, Windows-планировщик для него не нужен.
engines/native — существующий клиент и интеграция с прошивкой.
assets/native — готовые ARM-бинарники; пересобирать для обычной установки
не нужно. engines/bridge сохранён как исходный код Linux-версии, но Windows
CLI принимает только native. Не объявлять мост проверенным в Windows.

КОМПЛЕКТ И ЗАВИСИМОСТИ
windows/runtime — официальный embedded Python 3.13.17 x64.
windows/vendor — Paramiko и Windows-библиотеки, websocket-client.
alisa_cli/_vendor — prompt_toolkit и другие зависимости готового Linux CLI.
assets/vpn/windows-amd64 — Xray 26.10.21 и sing-box 1.12.0 для валидатора.
windows/dependencies.json — точные версии, официальные URL и SHA-256.
scripts/fetch_windows.py — загрузка и проверка зависимостей для пересборки.
scripts/bundle_windows.py — сборка переносимой папки и SHA-256 манифеста.
windows/source-files.json — список исходников для сборки без Git.
windows-package.json относится к этому комплекту. Старый Linux-манифест
package-manifest.json намеренно не включён.

ЧТО УЖЕ ПРОВЕРЕНО В LINUX / WINE
- 108 общих Linux-тестов CLI проходят.
- 14 Windows host-тестов проходят в Linux и в Windows Python через Wine:
  настоящий SSH сервер на loopback, 4 МиБ upload и 2 МиБ download,
  pinning ключа хоста, отказ при неверном пароле/смене ключа,
  установка собственного ключа через существующий identity,
  SOCKS-туннель как TCP relay, локальность DevTools, контроль файлов,
  сохранность state и неизвестных файлов при повторных обновлениях.
- Windows Python и скомпилированные crypto-библиотеки реально запускаются.
- Проверка пакета, установка на компьютер, повторный запуск и launcher
  проверены через Wine. Это не заменяет проверку в настоящей Windows.
- Windows SSH-клиент через Wine подключался к реальной Лайт 2 с root,
  проверял совместимость, передавал 1 МиБ с проверкой SHA-256 и stdin stream.
  Runtime колонки не перезапускали, вход/чаты не меняли.
- Синтетические конфиги обоих Windows VPN-ядер проходят проверку под Wine.
  Для Xray проверено также сообщение Configuration OK, а не только код 0.
- Пакет проверен на реальные локальные секреты; они не включены.
Безопасные журналы проверок приложены в evidence, если присутствуют.

ЧТО ОСТАЛОСЬ ПРОВЕРИТЬ / ГДЕ ОЖИДАЮТСЯ ПРОБЛЕМЫ
Главный непроверенный участок — реальный Chrome/Edge на Windows:
- live SQLite Cookies может быть заблокирован Windows-браузером; проверить
  автоматическое обнаружение входа и повторное использование старой сессии;
- Cloudflare и headless-импорт после обычного входа могут различаться;
  до успешной проверки на колонке прежнюю сессию не заменять;
- проверить владение PID, занятый профиль, отмену входа и закрытие окна;
- проверить вход через VLESS и без него, отсутствие запроса localhost через
  системный HTTP-прокси, отсутствие открытого DevTools после завершения;
- поддержать уже вошедший аккаунт без повторного принятия условий Voice;
- подтвердить Ctrl+C/Esc/стрелки и перерисовку в Windows Terminal и cmd.
Под Wine Xray не понимал некоторые Z:\home\... пути, но корректно проверил
тот же файл на C:\. Не считать этот артефакт Wine багом настоящей Windows.
У Xray наблюдался код 0 при ошибке открытия файла: смотреть и текст вывода.

КАК ПРАВИТЬ И ПЕРЕСОБИРАТЬ
Скопировать весь комплект с флешки в отдельную рабочую папку Windows.
Не править сразу установленную app: START-WINDOWS может вернуть файлы
из исходного пакета. Править исходники в рабочей копии.
После правок исходный манифест намеренно перестанет совпадать. Собрать
новый пакет в ДРУГУЮ пустую папку; для этого Git, pip и компилятор не нужны:

PowerShell, текущая папка — рабочая копия комплекта:
  & .\windows\runtime\python.exe -X utf8 -m unittest discover -s .\windows\tests -v
  & .\windows\runtime\python.exe -X utf8 .\scripts\bundle_windows.py --output "$env:USERPROFILE\Desktop\AlisaVoice-Windows-rebuilt"
  & "$env:USERPROFILE\Desktop\AlisaVoice-Windows-rebuilt\START-WINDOWS.cmd" --check-only
  & "$env:USERPROFILE\Desktop\AlisaVoice-Windows-rebuilt\START-WINDOWS.cmd"

Сборщик без Git читает windows/source-files.json. Новые исходные файлы
добавить в этот список до пересборки. Не добавлять туда state, ключи,
профили браузера, конфиги VPN, журналы с секретами или папки сборки.
Можно локально git init для удобства; remote/push пока не нужен.
Исправления и заполненный 03-RESULTS-TEMPLATE.txt вернуть на флешку.
