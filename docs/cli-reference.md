# Alisa Voice — установщик и управление

Версия для Linux x86_64 и Windows x64 пакет нативного режима. Требуются свои **root и SSH**: адреса, аккаунты и ключи разработчика не нужны. Установщик сверяет модель и точную пару SHA-256 maind/VQE. Нативный режим допускает Лайт 1/2 и Станцию 2 (`yandexmidi`); мост — только Лайт 2. Неизвестная пара хешей вызывает предупреждение, с которым установка разрешена. Это не подтверждение ABI новой сборки. Проверки модели, архитектуры, компонентов и целостности пакета обязательны. Получение root в установку не входит. [Лайт 1 и ограничения](lite1.md), [Станция 2](firmware-compatibility.md#яндекс-станция-2-yandexmidi).

Запуск из этой папки:

```bash
python3 alisa.py
```

Локальная установка команды `~/.local/bin/alisa`:

```bash
./install-linux.sh
~/.local/bin/alisa
```

Сначала выбирается режим. У них отдельные настройки и аккаунты; одновременно колонкой управляет один режим.

| Режим | Где работает GPT | Нужен ПК после настройки |
|---|---|---|
| Нативный | На колонке, C++ / WebRTC NetEq | Нет |
| Мост | В Chromium на Linux, колонка передаёт обработанный микрофон и воспроизводит звук | Да |

Главное меню нативного режима состоит из шести строк: GPT, настройки, аккаунт, VPN, обслуживание и смена режима. Пункт **«GPT — запустить / остановить»** показывает состояние при выделении, а по Enter проверяет текущее состояние и выполняет соответствующее действие. Фразы, голос, подсветка и переключатели автозапуска собраны в **«Настройках»**. Мастер, место, SSH, проверки, обновления и удаление находятся в **«Установке и обслуживании»**.

Меню управляется **↑/↓** и **Enter**; **Пробел** переключает автозапуск GPT/VLESS. **Home/End** переходят к первому/последнему пункту. Сведения показываются справа в колонке постоянной ширины, в узком терминале — снизу. Локальные настройки, справка и кэш появляются сразу. Только новые сетевые запросы ожидают короткой остановки на пункте — 0,35 секунды. Между данными не появляется общая справка; ответ от ранее выделенного пункта не заменяет текущую панель. У пункта «Назад» дополнительного текста нет.

В нативном режиме **«Настройки → Подсветка в паузах GPT»** включает голубую волну, пока чат открыт, но ответ не звучит. По умолчанию она выключена, в том числе при обновлении прежних настроек. Переключается Enter или пробелом и применяется без перезапуска разговора. Цвет и анимация ответа выбираются отдельно в «Подсветке»; вариант «Выключена» гасит всю индикацию GPT.

```bash
alisa native settings listen-on
alisa native settings listen-off
```

При входе в нативный GPT штатный музыкальный плеер получает команду паузы. Если команда открытия чата ещё распознаётся Алисой, пауза ожидает завершения этого ввода. Освобождение аудиофокуса после закрытия GPT само по себе не включает музыку заново; продолжить её можно обычной командой Алисе.

Кэш состояния действует 5 секунд, компонентов и места — 30 секунд, сети — 60 секунд. Enter в проверке обновляет данные вручную; выделение GPT только читает состояние, а запуск/остановка и голосовой тест требуют Enter. Фонового опроса без перемещения по меню нет. Подменю и выделение сохраняются после команды, старый текст терминала между командами не появляется. **Esc** возвращает назад и отменяет ввод без сохранения, **Ctrl+C** выходит после завершения начатой операции. Мастер и ввод настроек используют отдельные диалоги с возвратом в меню.

Основной текст использует цвета темы терминала, выбранный пункт выделяется инверсией. При перенаправлении вывода остаётся JSON для диагностики. Компоненты интерфейса входят в пакет и работают на компьютере установки: pip и память колонки им не нужны.

При первой установке после выбора режима **мастер запускается сам**. Он проходит SSH/root/модель/компоненты, внешний IP и страну, затем по очереди предлагает подключение, автозапуск, голосовые фразы и подсветку. Отмечать «настроить фразы» или «выбрать подсветку» в общем списке не нужно: эти настройки предлагаются всегда. Можно оставить показанные фразы и сохранённый VLESS без повторного ввода ссылки. После этого мастер показывает состав и место, устанавливает всё, запускает режим и предлагает вход и проверку голоса. Выполнять эти операции отдельно через меню не требуется. **Поиска по сети нет**: мастер явно просит IP колонки, SSH-порт (по умолчанию 2222), пользователя (root) и скрытый пароль. При первом подключении показывается отпечаток ключа SSH для подтверждения. Пароль используется однократно для входа и установки отдельного ключа, не сохраняется и не передаётся через аргументы процессов или файлы. Если доступ по ключу уже есть, поле пароля можно оставить пустым. Последующие запуски и автозапуск используют созданный ключ. Для браузерного входа нужен рабочий стол Linux.

Фразы задаются **после «Алиса»**. По умолчанию: «открой чат», «закрой чат», «создай новый чат», «открой предыдущий чат». Доступны радуга, постоянные цвета, пульсация и отключение GPT-подсветки. Штатная индикация восстанавливается при выходе. Фразы, подсветка и голос вынесены в отдельные пункты. При выборе подсветки стрелками на колонке сразу показывается демо цвета или анимации: Enter сохраняет выбор, Esc восстанавливает прежнее состояние. Демо использует один временный SSH-поток и не перезапускает GPT; при активном разговоре чужая индикация не перехватывается, причина показана в меню. Физическое выключение микрофона сохраняет приоритет. В нативном меню отдельно выбирается сохраняемый голос GPT.

## Управление

```bash
alisa native install                 # мастер установки
alisa native doctor                  # диагностика
alisa native ssh                     # изменить IP, порт и вход SSH
alisa native network                 # IP/страна именно колонки
alisa native start                   # также запускает настроенный VLESS
alisa native stop
alisa native toggle                  # запуск / остановка по текущему состоянию
alisa native status
alisa native login                   # вход и автоматическое сохранение
alisa native login change            # смена через отдельный новый профиль
alisa native logout                  # удалить локальный вход
alisa native settings                # фразы и подсветка
alisa native voice cove
alisa native verify                  # короткий настоящий голосовой ответ
alisa native autostart on
alisa native autostart off
alisa native autostart configure     # прямые переключатели GPT / VLESS
alisa native storage                 # место, размер и запас для установки
alisa native help                    # как работает мастер
alisa native uninstall --dry-run     # посмотреть список без удаления
alisa native uninstall               # удалить программу с подтверждением

alisa native vpn configure           # скрытый ввод ссылки, выбор сервера
alisa native vpn start
alisa native vpn stop                 # закрыть GPT, сохранить запрет прямого выхода
alisa native vpn status
alisa native vpn autostart
alisa native vpn disable              # явный выбор режима без VPN

alisa bridge install
alisa bridge start
alisa bridge stop
alisa bridge login
alisa bridge logout
alisa bridge autostart on
alisa bridge autostart off
```

Подключение из мастера использует явно введённые параметры и собственный файл проверенных ключей; локальные SSH-псевдонимы не требуются. **После первого успешного входа IP, порт, пользователь и путь к отдельному ключу запоминаются.** При повторной установке можно выбрать сохранённое подключение без нового ввода пароля либо изменить данные; поля редактирования заполнены прежними значениями. Команда `native ssh` или `bridge ssh` открывает их напрямую. В командном режиме также доступны `--host`, `--port`, `--user`, `--identity` и alias из `~/.ssh/config`. Диагностика и установка не отключают проверку ключа хоста и не заменяют изменившийся ключ молча. Для предварительной проверки файлов без установки: `native install --dry-run` или `bridge install --dry-run`.

## Место и удаление

Перед подтверждением мастер показывает свободное место колонки и компьютера, размер выбранных компонентов, пиковое место для обновления, запас 8 МиБ и оценку остатка. Уже совпадающий VPN-бинарник повторно не учитывается как новая передача. При обновлении учтено временное сосуществование старого файла и его копии `.new`. Строка «Не хватает места» появляется только при реальном дефиците и показывает недостающий объём для колонки или ПК. Недостаток места блокирует установку до записи файлов. Сжатие UBIFS и служебные расходы делают окончательный остаток оценкой. Это можно проверить в «Установка и обслуживание → Место и компоненты». Отсутствующие компоненты в диагностике перечисляются только при их обнаружении и подписаны отдельно от места.

«Установка и обслуживание → Удалить программу» показывает объём удаления и требует подтверждения. Удаляемые файлы сначала копируются в приватный каталог `~/.local/state/alisa-voice/<режим>/uninstall-backups/`. Затем режим останавливается, его автозапуск отключается, удаляются только перечисленные программные файлы. SSH, root, вход ChatGPT и чаты остаются; повторная установка может использовать сохранённые данные. Аккаунты других режимов и общий CLI на ПК не удаляются. Чужие файлы и каталоги целиком не стираются.

## VLESS

Нативный режим принимает одиночный `vless://`, списки ссылок, обычную/URL-safe Base64, JSON Xray/Incy, JSON sing-box и YAML Clash с независимыми VLESS-серверами. В меню можно выбрать формат запроса Incy или Happ. Поддержаны TCP, WebSocket, gRPC, HTTPUpgrade, XHTTP, TLS и Reality. Для XHTTP автоматически выбирается Xray 26.10.21 с собственным TUN; для остальных транспортов — sing-box 1.12.0. На колонке хранится один выбранный VPN-бинарник. Составные цепочки и отдельный XHTTP download endpoint не преобразуются. Количество пропущенных записей показывается. Ограничение импорта: 256 конфигураций, до 256 записей в каждой, ответ до 2 МиБ.

Импорт не означает, что провайдер разрешает этот клиент. Если приходит **App not supported**, установка VPN прекращается, рабочая конфигурация сохраняется. Можно экспортировать отдельную ссылку VLESS из своего приложения. Зашифрованные `happ://`/`incy://` ссылки и чужая HWID-привязка не расшифровываются.

HTTPS и UDP/WebRTC процесса GPT направляются через отдельный TUN, SO_MARK и таблицу 150. Основная таблица маршрутизации Алисы и SSH не меняется. При потере VPN разговор закрывается; маршрут `unreachable` сохраняет запрет прямого выхода IPv4/IPv6. Сам процесс VPN остаётся немаркированным. Состояние VPN контролируется в фоне; сетевой health-check выполняется раз в 20 секунд. VLESS требует примерно 40 МиБ места для ARM-бинарника плюс память процесса; реальное потребление зависит от трафика.

Остановка VPN и отключение его использования — разные действия. `vpn stop` сохраняет запрет, `vpn disable` явно разрешает запуск GPT без VPN. Если автозапуск GPT включён, а обязательный VLESS при загрузке не работает, GPT не запускается; Алиса остаётся доступна. Включение автозапуска одного режима отключает автозапуск другого. Изменяется только собственная init-запись на колонке; корневой раздел возвращается в прежний режим монтирования.

## Аккаунты, доступность и лимиты

При входе открывается обычный Chromium с отдельным профилем, без подключения отладчика во время авторизации. Войдите на сайте: CLI автоматически замечает появление сохранённой сессии и ждёт завершения её записи. Нажимать дополнительную кнопку не нужно. Затем закрывается только окно выделенного профиля и выполняется фоновая проверка сессии. Esc отменяет ожидание. Пункт «Войти» использует текущий профиль; «Сменить аккаунт» открывает отдельный новый профиль, чтобы прежний вход не был принят автоматически. После успешной смены предыдущий выделенный профиль остаётся в приватной истории аккаунтов. Нативный режим проверяет новый вход на самой колонке перед заменой прежнего. При отмене или неуспешной проверке прежняя сессия сохраняется. Браузер при обычной нативной работе колонки не нужен; мост сохраняет свою браузерную сессию. `logout` удаляет вход этого клиента и архивирует указатели чатов; это не глобальный выход со всех устройств. При смене аккаунта прежние чаты не подмешиваются новому.

Проверка сети показывает только внешний IP, страну и итог: RU — «Требуется VPN», другая определённая страна — «Пройдена». В нативном режиме запрос выполняет колонка через выбранное подключение GPT, в мосте — Linux-ПК. При ошибке определения страна остаётся неизвестной. Проверка IP не обращается к ChatGPT и не запускает голос; отдельный тест голоса доступен после входа. Тариф не используется как гарантия доступа. Исчерпание голосового лимита, ошибка входа или соединения закрывают разговор и освобождают управление Алисе; автоматического бесконечного повторения запросов нет.

Реальные Free и Plus проверены в обоих режимах. Go-аккаунта для живой проверки нет. Обработка ошибок не зависит от названия тарифа. В обоих режимах verify проверяет настоящий звуковой ответ: мост подаёт короткую синтетическую фразу через свой виртуальный микрофон и проверяет звук ответа, затем возвращает Алису.

## Файлы и проверка

Настройки, подписки и браузерные профили: `~/.local/state/alisa-voice/{native,bridge}` с правами 0700/0600. Их нет в установочном архиве. На колонке: `/data/opt/alisa-standalone` и `/data/opt/alisa-cli`; мост использует `/data/opt/alice-voice`. Учётные данные и сохранённые чаты при обновлении движка сохраняются. Нативный установщик проверяет manifest, SHA-256 передачи и откатывает заменяемые файлы при ошибке.

Тесты: `python3 -m unittest discover -s tests -v`. Сводка живых проверок — [validation.md](validation.md). Локальный архив создаётся `python3 scripts/release.py`; готовые пакеты доступны в GitHub Releases. Лицензии компонентов: [THIRD-PARTY.md](../THIRD-PARTY.md).

Windows-пакет нативного режима запускается через `START-WINDOWS.cmd` и содержит Python/Paramiko. Проверен один Windows 11 x64 / Edge; Windows 10 и неизвестные прошивки на настоящей Windows ещё требуют прогона. Моста Windows в этой ветке нет. [Результаты проверки](windows-validation-20261030.md).

## Применение настроек без перезапуска

Фразы перечитываются агентом при каждой команде; после сохранения файла перезапуск не нужен. Подсветка нативного клиента меняется командой контроллеру, а моста — через локальные настройки индикатора. Голос сохраняется для следующего разговора. Неизменённые фразы и цвет не вызывают SSH-записей или перезапуска. Для старого нативного клиента CLI предлагает явное обновление, не скрытый перезапуск.

На проверенной колонке сохранение фраз заняло около 0,44 с, подсветки — 0,87 с, голоса — 0,46 с. Настройки менялись при активном голосовом соединении; PID клиента, аудиопроцессы и счётчик разговоров не изменились.

## Меню VPN и повторная установка

На странице «VPN / VLESS» доступны запуск, остановка, сервер/подписка, переключатель автозапуска, «Не использовать VPN» и «Удалить VLESS и его файлы». После ввода ссылки и выбора сервера CLI спрашивает об автозапуске. Повторный ввод тех же параметров проверяет конфигурацию и сохраняет настройки без перезапуска GPT/VPN.

«Остановить VPN» сохраняет требование VPN для GPT. «Не использовать VPN» выбирает прямое подключение, оставляя программу и сервер. «Удалить VLESS и его файлы» после подтверждения удаляет VPN-движки, конфигурацию, список серверов, активную ссылку подписки и флаги VPN на колонке и ПК. Общие файлы нативного клиента, вход, чаты и SSH остаются. Копия удаляемого содержимого сохраняется в приватной `native/vpn-removal-backups/`.

```bash
alisa native vpn remove --dry-run  # посмотреть состав удаления
alisa native vpn remove            # удалить с подтверждением
alisa native vpn autostart-on
alisa native vpn autostart-off
```

Уже настроенный режим показывает «Настроить / переустановить». Повторный мастер объясняет, что вход и чаты сохраняются, показывает совпадающие файлы и объём передачи, затем сообщает текущую операцию и прошедшее время. Нативный установщик копирует только отличающиеся программные файлы. Если файлы совпадают, клиент и аудиопрофиль не перезапускаются; настройки применяются к работающему клиенту. Проверка и применение параметров при этом всё равно выполняются. Мастер использует текущий установочный пакет, не ищет новую версию проекта на GitHub.

В меню аккаунта «Войти» использует текущий выделенный браузерный профиль, «Сменить аккаунт» — чистый профиль с сохранением старого до успешной проверки, «Выйти» удаляет вход этого клиента. Пояснения показываются при выделении.

## Обновление версии приложения

**«Установка и обслуживание → Обновления программы»** проверяет GitHub Releases. При запуске CLI новая версия предлагается с вариантами «Обновить», «Не сейчас» и «Больше не спрашивать». Последний отключает предложения при запуске, а ручной пункт остаётся доступен. Переключатель на странице обновлений включает предложения обратно.

```bash
alisa --version
alisa update
alisa update check
alisa update ask-off
alisa update ask-on
```

В Windows аргументы те же, команда — установленный `alisa.cmd`. Обновляются приложение ПК и компоненты установленных режимов с сохранением данных; перед заменой программа требует закрыть голосовой чат. Прежняя папка сохраняется для отката.
