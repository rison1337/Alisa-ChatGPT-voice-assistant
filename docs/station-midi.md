# Станция Миди: экспериментальная поддержка

Модель `cucumber` не следует путать со Станцией 2 (`yandexmidi`).
Аппаратные наблюдения и ограничения перечислены в
[совместимости прошивок](firmware-compatibility.md).

## Голос и вход

Native-профиль Миди использует усиление захвата ×16. Остальные модели сохраняют
свои настройки (×16 у Станции 2 уже было до этого изменения).
Windows SSH теперь допускает серверный метод `none` после проверки сохранённого
ключа сервера. Это устраняет расхождение с OpenSSH на подготовленных Dropbear
с разрешённым входом без пароля. Установка отдельного ключа проверяет именно
вход ключом, без повторного обхода через `none`.
Видимое окно входа открывает `/auth/login`; это не исправляет неисправный SOCKS.

## Оформление

Кольцо Миди — 24 BGR-пикселя в fb0, логотип — 6 BGR-пикселей в fb1.
Размер и формат проверяются перед записью. Эффект rainbow использует
бирюзовые и фиолетовые следы; промежуточные кадры запрашиваются каждые 60 мс.
Это интервал ожидания, а не гарантия постоянной частоты кадров.
При неизвестном mute или чужом кадре применяется существующая логика уступки
управления. Физический mute на Миди ещё требует аппаратной проверки.

Матрица цифр с периодическим `GPT` сохранена отдельным `midi-clock.sh`.
`GPT` — оформление, не определение версии модели сервиса.
Для публичной ветки эффект **выключен по умолчанию**. Включение требует явной
переменной окружения `ALISA_MIDI_MATRIX=1` у процесса индикатора; отдельного
пункта меню пока нет. Рабочие настройки автора этим PR не изменяются.

Часы используют временные bind-mount каждого сегмента на двух LED-контроллерах.
Штатные записи идут в временные файлы, при завершении helper возвращает
последние значения. Сторож следит за владельцем и временем последнего кадра.
Перед восстановлением проверяется принадлежность mount этому сеансу.
Запись кадра, подключение сегментов и восстановление используют общий замок.
При завершении сеанс перестаёт принимать новые записи; проснувшийся после
остановки процесс уже не может снова захватить дисплей. Временные файлы
удаляются по точным путям после снятия mount, без рекурсивного удаления.
Оборванная запись времени последнего кадра не останавливает сторожа.

## Проверки восстановления

Автоматические файловые тесты проверяют сбой каждого из 47 mount (два
контроллера и 45 сегментов), чужой mount, испорченный файл яркости, завершение
владельца, просроченную/оборванную служебную запись и гонку с записью кадра.

На одной cucumber-dvt2 новый helper отдельно запущен из временной папки.
Проверены обычное завершение, SIGTERM, SIGKILL и SIGSTOP с последующим SIGCONT:
каждый раз захватывались 45 сегментов, затем все наложения снимались, основной
клиент оставался idle. Это проверка возврата управления через SSH; внешний вид
штатных часов после каждого случая отдельно владельцем не подтверждался.
Рабочая установленная версия приложения при этом не заменялась.

## Что ещё нужно до включения матрицы по умолчанию

- Проверить реальные сбои ввода-вывода на устройстве: файловые тесты частичного
  захвата не заменяют аппаратную проверку каждого этапа.
- Проверить аппаратный mute, перезагрузку, возврат штатных часов и автозапуск.

Эти ограничения относятся к экспериментальному helper; обычные часы остаются
под управлением прошивки, пока матрица не включена явно.
