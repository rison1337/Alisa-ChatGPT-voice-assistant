# Проверка заводских прошивок Лайт 2

Описанные ниже изменения добавлены в 0.3.9. Формат factory остаётся экспериментальным.

Factory и обычная retail-система могут использовать разные варианты локального
протокола. Определение модели и разрешение неизвестной пары хешей с предупреждением
не подтверждают совместимость команд, фокуса или микрофонов factory.

В [issue #16](https://github.com/rison1337/Alisa-ChatGPT-voice-assistant/issues/16)
для `yandex,plum` / `0.10.1.22.3669974551.20251217.factory-10` автор сообщил
верхнеуровневые protobuf-поля `3` (состояние) и `210` (capability). Проверенные
retail-сборки используют поля `252` (содержимое) и `253` (тип).

## Экспериментальный формат агента

`ALICE_NATIVE_WIRE_FORMAT=fields` выбирает прямые поля в приёме, отправке команд
и аварийном освобождении фокуса. `wrapped` — исходный формат, используется
по умолчанию. Выбор должен попасть в окружение процесса агента до запуска;
он не переключается во время разговора. `native.wire_format` в статусе показывает
реальный выбранный формат. Неверное значение останавливает запуск агента.

В режиме `fields` распознанный финальный результат не требует retail-флага
`f15.f4=1`: по отчёту автора на указанной factory он не выставляется. Проверки
финальности (`f15.f2=1`), состояния BUSY, идентификатора запроса и повторов
сохраняются. Значение `f4` в закрытом протоколе не установлено. В режиме `wrapped`
его прежняя проверка остаётся обязательной.

Оба режима проверены против локального IPC-стенда: сообщения состояния,
распознанная команда, пауза музыки, подтверждение фокуса только по нашему request ID,
отказ от повреждённых сообщений и очистка фокуса сторожем после SIGKILL.
Это не аппаратное подтверждение фокуса на указанной factory. Поддержка внутреннего
регистрационного хендшейка `maind` пока не установлена; его необходимость
в отчёте автора — отдельная гипотеза. Автоматически включать режим `fields`
по одному номеру прошивки установщик не пытается.

## Выбор сертификатов

Голосовой запрос, обновление входа и `network-check` / `vpn-health` используют
одинаковые правила:

1. Непустой `ALISA_CA_FILE`.
2. Непустой `SSL_CERT_FILE`.
3. Читаемый `/system/vendor/quasar/certs/ca-certificates.crt`.
4. Читаемый `/system/vendor/quasar/ca-certificates.crt`.
5. Системное хранилище библиотеки TLS, если ничего из списка не задано и не найдено.

`SSL_CERT_DIR` дополнительно задаёт каталог сертификатов в формате OpenSSL.
Неверный явно указанный файл не заменяется другим автоматически. Проверка цепочки
сертификата и имени сервера остаётся включённой. Клиент с этими изменениями
выбирает второй путь без симлинка в системном разделе.
