# Неизвестная прошивка: предупреждение и установка

## Экспериментальная Станция Миди (cucumber)

Станция Миди распознаётся по точному маркеру `yandex,cucumber` в device tree
(описании аппаратуры). Это отдельная модель: `yandexmidi` / `yandex,station-midi`
в проекте обозначают **Станцию 2**, а не Миди. Один номер прошивки или название
процессора недостаточны для определения модели.

На одной Миди владелец подтвердил голосовой ответ, повторный разговор,
подсветку кольца и логотипа, цифры с периодическим `GPT` на дисплее.
Прошивка: `0.369.1.46.4778262955.20261013.160`.
Маркер платы: `yandex,cucumber-dvt2`, базовый маркер: `yandex,cucumber`.
Ядро сообщает `aarch64`, при этом maind и VQE на этом устройстве — ARM ELF32;
использовался существующий armhf payload без пересборки аудиобиблиотек.

Прочитанные SHA-256:

- maind: `ae53daaf1d1867744017bb6939d7fa2c95f0d76468f8472a273ab041a895642b`;
- VQE: `b44edb57216c82921f92f97a76b16ac97833b1a3172d8d4f63c6bb42ff0eac53`.

Поддержка пока экспериментальная: пара намеренно не добавлена в список
проверенных сборок, предупреждение сохраняется. Доступен только native;
Linux-мост для Миди не включён. В профиле микрофона применяется усиление ×16:
после его включения владелец подтвердил ответы на обычную речь.
Это наблюдение на одном устройстве, а не измерение качества на всех Миди.

На рабочей установке физическое переключение mute подтверждено по gpio-505
(hi → lo → hi); по наблюдению владельца ответы прекращались и возобновлялись.
Отсутствие передачи аудиоданных отдельно не измерялось.
На рабочей установке также выполнена обычная перезагрузка: сменился boot ID,
VPN стал ready, клиент автоматически вернулся в idle с подключённым агентом.
После этой загрузки владелец подтвердил голосовой ответ и привычную подсветку.
Не проверены другие ревизии и прошивки. Затем полная сборка PR установлена
штатным Windows-установщиком и native-updater: все 35 файлов клиента совпали
с пакетом, агент подключён, выбор матрицы сохранён. Финальный голосовой тест
после обновления ещё ожидает подтверждения владельца.
Новый helper часов также отдельно проверен из временной папки на завершение
процесса и возврат управления дисплеем.
Описание оформления и оставшихся проверок — [station-midi.md](station-midi.md).

## Общая политика неизвестных прошивок

Начиная с `0.3.0` неизвестная пара SHA-256 `maind`/VQE больше не блокирует установку на распознанной Лайт 1/2. Это изменение политики установки по запросу владельца; оно не доказывает совместимость всех прошивок.

Причина — [issue #2](https://github.com/rison1337/Alisa-ChatGPT-voice-assistant/issues/2): Лайт 2 с прошивкой `0.372.1.13.4794666714.20261021.136` остановилась на прежнем списке разрешённых хешей. В issue нет результата запуска наших аудиомодулей на этой сборке. Её пара хешей используется в регрессионном тесте:

- maind: `5719ba6cbe756d2d60bc7755e13493340a7a85a9269f5a5b7845f13ee09e6986`;
- VQE: `838e498b40508e2647633f6b5440759ead5a6e22b2acb33c739b39eb04a54f67`.

## Поведение CLI

Для известной пары показывается **«Проверенная сборка»**. Для другой читаемой пары — **«Совместимость не проверена»** и предупреждение:

> Эта сборка прошивки ещё не проверена. Установка разрешена, но работа микрофона, звука и голосовых команд не гарантируется.

Можно пройти обычный мастер или использовать `native install --yes`. Дополнительного скрытого флага для неизвестной версии нет. Подтверждение установки остаётся обычным последним шагом мастера.

Нативный режим допускает Лайт 1, Лайт 2, Мини 2 и Станцию 2 (`yandexmidi`), а также Мини 3 (`bergamot`); Linux-мост — Лайт 2 и Мини 2. Обе проверки моста, включая проверку перед копированием профиля, используют ту же политику. Прямой инструмент `engines/native/tools/deploy.py` также использует её.

Проверки SSH/root, точного идентификатора модели, ARM-архитектуры, читаемости компонентов, свободного места, необходимых утилит и SHA-256 установочного пакета сохраняются. Неподходящая структура launcher/ALSA/речевых pipeline всё ещё останавливает подготовку профиля. Мост Лайт 1 не включён этим изменением.

## Диагностический JSON

В `doctor` сохранено поле `firmware_abi_supported`: оно по-прежнему `true` только для ранее проверенной пары своей модели. Новая версия не выдаёт неизвестную сборку за проверенную.

Добавлены `firmware_status`, `firmware_files_present`, `firmware_version`, `firmware_sha256` и `warnings`. Поле `ok` означает успешное прохождение обязательных проверок установки. Поэтому допустимо `ok=true` вместе с `firmware_abi_supported=false` и предупреждением. Ошибку чтения maind/VQE нельзя использовать как разрешение неизвестной версии.

```bash
alisa native doctor
alisa native install --dry-run
```

В Windows используйте установленный `alisa.cmd` с теми же аргументами. Эти команды не являются голосовым тестом. Нативный dry-run не копирует модули и не переключает профиль колонки.

## Подтверждения и границы

На фикстурах проверены точная пара из issue, неизвестная Лайт 1, известные сборки, обязательные отказы, целостность повреждённого пакета и отсутствие второго запрета хеша в мосте. Саму новую Лайт 2 из issue в этой ветке не запускали. Статическое исследование архива Лайт 1 не заменяет живую проверку звука и команд на каждой версии.

Нативный клиент и бинарные аудиомодули этим изменением не пересобирались. Новая политика не исправляет несовместимый ABI, если такой обнаружится. Отключение обновлений прошивки и проверки установочного архива продолжают работать как раньше.

## Яндекс Станция 2 (yandexmidi)

Модель добавлена в `BUILDS` как `yandexmidi` (device-tree `yandex,station-midi`, встречается также `yandexmidi`/`station-midi`). Это Станция 2; Станция Миди (`cucumber`) — другая модель. Поддержка основана на [PR #3 от serbo26-lab](https://github.com/rison1337/Alisa-ChatGPT-voice-assistant/pull/3). Автор сообщил об аппаратной проверке на одной станции с прошивкой `0.369.1.46.4778263334.20261013.295`. В `BUILDS` сохранена её пара SHA-256:

```text
maind: 9ad1476ee37df3e401a8426df7710f8f3d2d0695e01d0b949d99a5a8b562a4d2
VQE:   e3f80b79cd5b7f9422b790b3fe81cc41883e1c07914e6b474f4fd9313e3b84af
```

Другие сборки получают статус **«Совместимость не проверена»** и предупреждение; обязательные проверки сохраняются. Две особенности модели обрабатываются автоматически:

- **Переключатель микрофона.** В debugfs он размечен иначе: строки `MUTE_SWITCH`/`MUTE_STATE` с активно-низкой полярностью (`lo` — микрофон включён). Прежде клиент не находил `|mute-switch hi` и затирал запись нулями, из-за чего ChatGPT слышал тишину. `mute_gpio.so` конвертирует список при каждом открытии: нажатие mute, неизвестное состояние или ошибка чтения запрещают передачу микрофона. Список читается потоком; состояния после первых 2048 байт также учитываются. Каждый читатель получает отдельный файл без общего временного имени. Формат Лайт 2 передаётся без изменений, сценарий Лайт 1 со статичным файлом сохранён.
- **Уровни микрофона.** По замерам автора, буфер `vqe_0` отдаёт нормализованный float32 примерно на 25 дБ тише (речь ≈ −51 dBFS против −25 dBFS на Лайт 2). `vqe_tap` читает `ALICE_CAPTURE_GAIN`; установщик выставляет `16` для `yandexmidi` (по умолчанию `1` — уровни Лайт 1/2 сохраняются). Усиление применяется к копии PCM с ограничением пиков; исходный VQE-буфер не меняется. Некорректные значения усиления заменяются на `1`.

С версии 0.3.4 подсветка GPT доступна на панели из 88 светодиодов через `/dev/fb0` (89×1, RGBW, 356 байт, последний пиксель — чёрное дополнение). Карта панели и первые аппаратные проверки получены из [PR #5 от serbo26-lab](https://github.com/rison1337/Alisa-ChatGPT-voice-assistant/pull/5). Радуга, постоянные цвета, пульсация и живое демо доступны в общем CLI Linux/Windows. Подсветка в паузах выключена по умолчанию; сохранённый ранее цвет «Выключена» не заменяется автоматически. Физический mute и неизвестное состояние GPIO запрещают запись, включая очистку при выходе. Внешний красный кадр получает приоритет. Если прошивка перерисовала обычный цвет, следующий кадр GPT восстанавливает индикацию. При закрытии стирается только собственный кадр; демо восстанавливает прежний. Чтение и запись framebuffer не образуют атомарную блокировку с прошивкой: очень короткое наложение при одновременной записи остаётся возможным. Мост отклоняется ещё при предварительной проверке.

В отчёте автора PR указаны Windows 11 / Edge, вход в ChatGPT, голосовой диалог, команды открытия/закрытия и перезагрузка с автозапуском. Собственного аппаратного прогона Станции 2 нет. Локальные проверки выполняются на синтетических GPIO/аудиоданных и проверяют настоящий установочный payload; они не подтверждают все версии прошивки.

При интеграции 1 ноября 2026 года прошли 186 тестов Linux, пять проверок модели/установочного payload и 29 тестов Windows host/launcher/updater в Windows Python под Wine. Windows-прогон использует UTF-8, как штатный `START-WINDOWS.cmd`. Проверены реальные преобразования PCM с усилением `1`/`16`, ограничение пиков, некорректные значения, неизменность исходного буфера и `errno`. Для mute проверены смена состояния между открытиями, длинный GPIO-список, неизвестные состояния и параллельные читатели. Linux- и Windows-архивы распакованы и проверены по внешним и вложенному native manifest. ARM-модули пересобраны; импортируемые символы доступны в сохранённых libc/libdl/loader glibc 2.30 Лайт 2. Это статическая проверка зависимостей, не запуск модулей на Станции 2.

Дополнительно новые модули проверены на настоящей Лайт 2 после обновления `0.3.2 → 0.3.3`: голосовое соединение, обработанный микрофон, ответ GPT без сбоев ALSA, закрытие чата, штатная озвучка Алисы и автозапуск после полной перезагрузки. Вход, чаты и настройки при обновлении сохранены; усиление ×16 в её профиль не попало. Этот прогон не заменяет проверку других моделей. Подробности: [релиз 0.3.3](release-0.3.3.md).

Проверки подсветки 0.3.4: переходы mute/неизвестного GPIO после захвата панели, внешний владелец, выход по команде/EOF/TERM/HUP, повтор одного цвета после перерисовки, геометрия framebuffer и сохранение кадра при закрытии демо проверены на файловых стендах. На настоящей Лайт 2 выполнены сценарии панели через временные файлы в её BusyBox и живое демо кольца с восстановлением яркости/триггеров. Это не аппаратная проверка панели Станции 2. Большой скрипт демо передаётся через stdin, потому что Dropbear этой Лайт 2 разрывает exec-запросы порядка 10 КБ; сценарий работает через одно соединение и удаляет временный файл при завершении.

## Яндекс Станция Мини 2 (yandex,station-mini2)

Модель добавлена в `BUILDS` как `mini2` на основе [PR #8 от roman-dynin](https://github.com/rison1337/Alisa-ChatGPT-voice-assistant/pull/8). Device tree — строго `yandex,station-mini2`; это не Мини 3. Автор проверил нативный режим и Linux-мост на одной колонке с прошивкой `0.369.1.46.4793643989.20261020.299`.

| Файл | SHA-256 |
|---|---|
| `maind` | `7ff114e08d46d48394f9d794f89dc941f3b217bdcd3ff1ef46f1cd80fada6ec1` |
| `libyandex_evil.so` | `fa7ad1544fe9ddfccedcf15acc031768345b0b8c7333bc1c0b47bc476dd4152f` |

VQE совпадает со сборкой Лайт 2; аудиомодули, усиление и протокол кадров не менялись. Три логические зоны подсветки отображаются на шесть физических попарно. Часы `mini2:white:clock*` не затрагиваются. Для моста `socat` также ищется в `/data/opt/entware/bin`.

У кнопки микрофона нет строки `mute-switch`: автор подтвердил защёлкнутое состояние на `gpio-414` (`lo` — mute) и обнуление VQE самим `maind`. Статический листинг для нативного клиента сохраняется; индикатор отдельно читает физический GPIO без этой подмены. При mute или неизвестном состоянии он возвращает триггеры прошивке без записи яркости, включая завершение процесса. Это новое поведение проверено на файловом стенде, в том числе с настоящим загруженным `mute_gpio.so`, без аппаратной проверки Мини 2.

Другие прошивки допускаются с предупреждением. Автозапуск после перезагрузки и живая Windows-установка на Мини 2 не подтверждены. Подробные результаты и ограничения: [Мини 2](mini2.md).

## Яндекс Станция Мини 3 (bergamot)

Нативный режим добавлен в 0.3.7 по PR #12; точные маркеры модели и пара хешей проверенной автором прошивки находятся в [главе Мини 3](mini3.md). Мост отклоняется до записи профиля. Кольцо BGR и сегменты дисплея обрабатываются только для этой модели. Профили, усиление и аудиомодули Лайт 1/2, Мини 2 и Станции 2 сохраняются. Клиент пересобран для необязательного отключения STUN; по умолчанию оно выключено.

## Платы Станции Лайт 2

Лайт 2 выпускается с платами Plum и Prune. Определение модели использует точные
маркеры `yandex,plum` и `yandex,prune` из device tree. Строка ревизии платы,
например `yandex,plum-evt2-aw21036`, сопровождается базовым маркером.
Один только `amlogic, axg` не определяет модель: эта платформа встречается
у разных колонок.

Распознавание Plum EVT1, Plum EVT2, Plum EVT2-aw21036 и Prune EVT2 проверено
на соответствующих свойствах device tree в проверках установщика Linux/Windows.
Это не аппаратный прогон каждой ревизии. Неизвестная прошивка распознанной
Лайт 2 разрешена с предупреждением; известный номер версии сам по себе
не заменяет проверку модели и наличия файлов.

Factory-система может отличаться от retail также локальным протоколом команд.
Распознавание модели не подтверждает работу аудиофокуса на factory.
[Экспериментальная проверка factory и выбор сертификатов](factory-compatibility.md).
