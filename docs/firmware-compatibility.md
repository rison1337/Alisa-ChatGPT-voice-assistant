# Неизвестная прошивка: предупреждение и установка

Начиная с `0.3.0` неизвестная пара SHA-256 `maind`/VQE больше не блокирует установку на распознанной Лайт 1/2. Это изменение политики установки по запросу владельца; оно не доказывает совместимость всех прошивок.

Причина — [issue #2](https://github.com/rison1337/Alisa-ChatGPT-voice-assistant/issues/2): Лайт 2 с прошивкой `0.372.1.13.4794666714.20261021.136` остановилась на прежнем списке разрешённых хешей. В issue нет результата запуска наших аудиомодулей на этой сборке. Её пара хешей используется в регрессионном тесте:

- maind: `5719ba6cbe756d2d60bc7755e13493340a7a85a9269f5a5b7845f13ee09e6986`;
- VQE: `838e498b40508e2647633f6b5440759ead5a6e22b2acb33c739b39eb04a54f67`.

## Поведение CLI

Для известной пары показывается **«Проверенная сборка»**. Для другой читаемой пары — **«Совместимость не проверена»** и предупреждение:

> Эта сборка прошивки ещё не проверена. Установка разрешена, но работа микрофона, звука и голосовых команд не гарантируется.

Можно пройти обычный мастер или использовать `native install --yes`. Дополнительного скрытого флага для неизвестной версии нет. Подтверждение установки остаётся обычным последним шагом мастера.

Нативный режим допускает Лайт 1, Лайт 2 и Станцию 2 (`yandexmidi`); Linux-мост — Лайт 2. Обе проверки моста, включая проверку перед копированием профиля, используют ту же политику. Прямой инструмент `engines/native/tools/deploy.py` также использует её.

Проверки SSH/root, точного идентификатора модели, ARM-архитектуры, читаемости компонентов, свободного места, необходимых утилит и SHA-256 установочного пакета сохраняются. Неподходящая структура launcher/ALSA/речевых pipeline всё ещё останавливает подготовку профиля. Мост Лайт 1 не включён этим изменением.

## Диагностический JSON

В `doctor` сохранено поле `firmware_abi_supported`: оно по-прежнему `true` только для ранее проверенной пары своей модели. Новая версия не выдаёт неизвестную сборку за проверенную.

Добавлены `firmware_status`, `firmware_files_present`, `firmware_version`, `firmware_sha256` и `warnings`. Поле `ok` означает успешное прохождение обязательных проверок установки. Поэтому допустимо `ok=true` вместе с `firmware_abi_supported=false` и предупреждением. Ошибку чтения maind/VQE нельзя использовать как разрешение неизвестной версии.

```bash
alisa native doctor
alisa native install --dry-run
```

В Windows используйте установленный `alisa.cmd` с теми же аргументами. Эти команды не являются голосовым тестом. Нативный dry-run не копирует модули и не переключает профиль колонки.

## Подтверждения и границы

На фикстурах проверены точная пара из issue, неизвестная Лайт 1, известные сборки, обязательные отказы, целостность повреждённого пакета и отсутствие второго запрета хеша в мосте. Саму новую Лайт 2 из issue в этой ветке не запускали. Статическое исследование архива Лайт 1 не заменяет живую проверку звука и команд на каждой версии.

Нативный клиент и бинарные аудиомодули этим изменением не пересобирались. Новая политика не исправляет несовместимый ABI, если такой обнаружится. Отключение обновлений прошивки и проверки установочного архива продолжают работать как раньше.

## Яндекс Станция 2 (yandexmidi)

Модель добавлена в `BUILDS` как `yandexmidi` (device-tree `yandex,station-midi`, встречается также `yandexmidi`/`station-midi`). Это Станция 2; Станция Миди (`cucumber`) — другая модель. Поддержка основана на [PR #3 от serbo26-lab](https://github.com/rison1337/Alisa-ChatGPT-voice-assistant/pull/3). Автор сообщил об аппаратной проверке на одной станции с прошивкой `0.369.1.46.4778263334.20261013.295`. В `BUILDS` сохранена её пара SHA-256:

```text
maind: 9ad1476ee37df3e401a8426df7710f8f3d2d0695e01d0b949d99a5a8b562a4d2
VQE:   e3f80b79cd5b7f9422b790b3fe81cc41883e1c07914e6b474f4fd9313e3b84af
```

Другие сборки получают статус **«Совместимость не проверена»** и предупреждение; обязательные проверки сохраняются. Две особенности модели обрабатываются автоматически:

- **Переключатель микрофона.** В debugfs он размечен иначе: строки `MUTE_SWITCH`/`MUTE_STATE` с активно-низкой полярностью (`lo` — микрофон включён). Прежде клиент не находил `|mute-switch hi` и затирал запись нулями, из-за чего ChatGPT слышал тишину. `mute_gpio.so` конвертирует список при каждом открытии: нажатие mute, неизвестное состояние или ошибка чтения запрещают передачу микрофона. Список читается потоком; состояния после первых 2048 байт также учитываются. Каждый читатель получает отдельный файл без общего временного имени. Формат Лайт 2 передаётся без изменений, сценарий Лайт 1 со статичным файлом сохранён.
- **Уровни микрофона.** По замерам автора, буфер `vqe_0` отдаёт нормализованный float32 примерно на 25 дБ тише (речь ≈ −51 dBFS против −25 dBFS на Лайт 2). `vqe_tap` читает `ALICE_CAPTURE_GAIN`; установщик выставляет `16` для `yandexmidi` (по умолчанию `1` — уровни Лайт 1/2 сохраняются). Усиление применяется к копии PCM с ограничением пиков; исходный VQE-буфер не меняется. Некорректные значения усиления заменяются на `1`.

Подсветка GPT для этой модели недоступна: мастер выставляет «Выключена», меню скрывает выбор цвета, а runtime отключает индикацию даже при старой настройке. Штатная подсветка Алисы сохраняется. Мост отклоняется ещё при предварительной проверке.

В отчёте автора PR указаны Windows 11 / Edge, вход в ChatGPT, голосовой диалог, команды открытия/закрытия и перезагрузка с автозапуском. Собственного аппаратного прогона Станции 2 нет. Локальные проверки выполняются на синтетических GPIO/аудиоданных и проверяют настоящий установочный payload; они не подтверждают все версии прошивки.

При интеграции 1 ноября 2026 года прошли 186 тестов Linux, пять проверок модели/установочного payload и 29 тестов Windows host/launcher/updater в Windows Python под Wine. Windows-прогон использует UTF-8, как штатный `START-WINDOWS.cmd`. Проверены реальные преобразования PCM с усилением `1`/`16`, ограничение пиков, некорректные значения, неизменность исходного буфера и `errno`. Для mute проверены смена состояния между открытиями, длинный GPIO-список, неизвестные состояния и параллельные читатели. Linux- и Windows-архивы распакованы и проверены по внешним и вложенному native manifest. ARM-модули пересобраны; импортируемые символы доступны в сохранённых libc/libdl/loader glibc 2.30 Лайт 2. Это статическая проверка зависимостей, не запуск модулей на Станции 2.
