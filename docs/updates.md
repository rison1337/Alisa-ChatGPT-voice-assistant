# Обновления Linux и Windows

Начиная с версии `0.3.0` приложение получает обновления из стабильных GitHub Releases для Linux и Windows.

## Предложение при запуске

CLI проверяет последний стабильный GitHub Release. При наличии пакета для текущей системы появляются три варианта:

- **Обновить** — скачать, проверить и установить.
- **Не сейчас** — продолжить с текущей версией; предложение остаётся включённым.
- **Больше не спрашивать** — отключить предложения при запуске, включая сетевую проверку для них.

Проверка кэшируется на 6 часов, запрос сведений ограничен 3 секундами. Отсутствие сети не мешает запуску CLI. Проверка сведений не подключается к колонке и не меняет её. Фоновой установки нет. Разработка в Git-копии не обновляется этим способом.

Ручная проверка и переключатель уведомлений находятся в **«Установка и обслуживание → Обновления программы»**. Отключение уведомлений не блокирует ручной пункт.

```bash
alisa --version
alisa update                 # проверить сейчас и предложить установку
alisa update check           # только сведения, без установки
alisa update ask-off         # больше не предлагать при запуске
alisa update ask-on          # снова предлагать
```

В Windows те же аргументы передаются установленному `alisa.cmd`. Если его папка отсутствует в PATH, используйте `%LOCALAPPDATA%\AlisaVoice\alisa.cmd`. В PowerShell полный путь запускается через `&`.

## Что заменяется

Сначала проверяются SHA-256 архива, пути и типы файлов, manifest, версия и платформа. Распаковка не исполняет код до этих проверок. Поддержаны Linux x86_64 и Windows x64. Обновление запускается из временного пакета; Windows освобождает старый Python перед заменой папки.

Затем программа проверяет состояние установленных режимов. Активный или открывающийся голосовой чат нужно закрыть. Работающие режимы останавливаются, приложение на компьютере заменяется с сохранением прежней папки, затем обновляются программные компоненты установленных режимов на колонке. Требуется доступный SSH. Возобновляются только режимы, работавшие до обновления; выключенный режим сам не запускается. Тестовый голосовой разговор автоматически не включается.

Настройки, входы ChatGPT, указатели чатов, SSH, VPN-конфигурация и автозапуск сохраняются. Процедура обновляет клиент и вспомогательные модули; отдельного автоматического обновления уже установленного VPN-ядра здесь нет. Смена сервера и управление VPN остаются в его меню.

При ошибке программа возвращает предыдущую папку приложения и пытается вернуть компоненты и работавшие режимы. Если восстановление не завершилось, CLI сообщает, что требуется проверка, и сохраняет результат. Не обещается восстановление после любой потери питания или недоступности колонки.

Предыдущие папки `app.previous*` в Windows и `alisa-voice.previous*` в Linux сохраняются. Неизвестные файлы старой программы остаются в этих копиях. Временные загрузки удаляются при последующих запусках только при совпадении контрольных сумм; изменённые и посторонние файлы сохраняются. Занятые DLL Windows удаляются при следующей возможности.

## Первая миграция и повторный мастер

В старой публичной версии нет нового меню: один раз запустите новый готовый установщик. После этого обновления доступны из CLI. Обычная повторная установка также сохраняет данные.

**«Настроить / переустановить»** использует уже установленный пакет и меняет параметры выбранного режима. **«Обновления программы»** получает новую версию с GitHub и обновляет приложение вместе с установленными компонентами. Эти действия не равнозначны.

## Проверки и границы

Дополнительно к прежним Linux/Wine-проверкам 30.10.2026 выполнен отдельный прогон updater на одном Windows 11 x64 с Edge и настоящей Лайт 2: self-update, откат, блокировка файлов, очистка временного пакета, меню, сохранение данных, обновление компонентов и возврат исходного состояния режима. Фаза `connecting` добавлена в запрет обновления во время разговора. Подробности и ограничения: [результаты updater](../CODEX-HANDOFF/05-UPDATER-WINDOWS-RESULTS.txt). Прежний [отчёт установщика](windows-validation-20261030.md) описывает другой прогон.

Найденная в первом прогоне потеря кода ошибки Windows исправлена: установленный `alisa.cmd` дожидается updater через отдельный управляющий процесс вне `app`. Успех возвращает `0`, откат и неполное восстановление — `1`; повторное открытие меню не стирает ошибку. Установщик также запускает CLI через этот процесс. Для перехода со старого запуска один раз установите исправленный готовый пакет и закройте прежний CLI. Прямой запуск `python alisa.py update` в Windows предлагает использовать `alisa.cmd` и отказывает до изменений. Подробности: [исправление и повторная проверка](../CODEX-HANDOFF/06-WINDOWS-EXIT-CODE-FIX.txt).

Подробный результат по-прежнему записывается в `%LOCALAPPDATA%\AlisaVoice\state\update-status.json` (при отдельном `ALISA_HOME` — в нём): `complete`, `rolled_back` или `recovery_needed`.

Публичный релиз ради проверки не создавался: использованы локальные ZIP с SHA-256 и синтетические версии. Получение реально более новой опубликованной версии с GitHub не проверено. Windows 10, Chrome, живой Go-аккаунт и аппаратная Лайт 1, включая её mute GPIO в GPT, этим результатом не подтверждаются.
