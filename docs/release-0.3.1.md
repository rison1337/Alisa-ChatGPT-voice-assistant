# Alisa Voice 0.3.1

Исправлено обновление при недоступной колонке. В 0.3.0 ошибка SSH ошибочно отображалась как остановленный нативный клиент: updater начинал замену программы, затем не мог ни установить, ни проверить возврат компонентов. Например, это происходило после смены Wi-Fi, когда в CLI оставался IP предыдущей сети.

- Перед заменой программы проверяются SSH, состояние клиента и возможность установки компонентов из нового пакета.
- Ошибка подключения больше не выглядит как остановка клиента или потеря входа ChatGPT. Updater показывает фиксированное понятное сообщение, без вывода приватного ответа SSH.
- После сбоя та же версия не предлагается снова при запуске; ручной повтор остаётся в меню обновлений.
- Из публичных исходников и нового Windows-пакета убраны внутренние инструкции передачи тестового комплекта.

Обновление доступно через `alisa update` в Linux и установленный `alisa.cmd update` в Windows. Проверьте, что IP и порт в настройках соответствуют текущей сети колонки. Настройки, вход ChatGPT, чаты, SSH, VPN и автозапуск сохраняются. Аудиоклиент и прошивка этим исправлением не меняются.

Проверено: 155 тестов Linux; успешный updater с настоящей Лайт 2 по SSH и отказ при закрытом SSH-порту без изменений программы и компонентов. Приложение на ПК для этого прогона изолировалось в отдельной папке. Файлы состояния ChatGPT и чатов на колонке до и после совпали. Под Wine пройдены 29 проверок Windows и общий набор updater (20 пройдено, один тест Linux пропущен); это не новый прогон на Windows 11.
