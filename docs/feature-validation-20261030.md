Возвращённый Windows-комплект проверен отдельно: [результаты](windows-validation-20261030.md). Исходники приложения в нём совпали с базой, подтверждения Windows 11/Edge сохранены. Прежний периодический ICE/WebRTC сбой новым исправлением не закрывался.

Адаптация Лайт 1 основана на [PR #1](https://github.com/rison1337/Alisa-ChatGPT-voice-assistant/pull/1), автор HuHguZ, head `df1b536eb161fded34657f7864e5e5ad5dd834b9`. Перенесены проверенная пара хешей, GPIO preload, micro LED, устойчивые записи и UTF-8. Вместо отдельного Windows login из PR сохранён наш проверенный Edge/Paramiko путь. Модель определяется по device tree, хеши — по точным именам файлов. Мост Лайт 1 блокируется. [Границы аппаратных свидетельств](lite1.md).

На колонке владельца выполнены только чтение статуса и doctor: Лайт 2 с поддержанной парой хешей, root/SSH доступны. Новые модули, updater и клиент на неё не устанавливались; питание, сеть и текущий вход не менялись.

## Автоматические проверки

- Linux: 138 общих тестов, успешно.
- Windows Python через Wine: 24 Windows host-теста, успешно.
- Windows Python через Wine: 17 updater-тестов, 16 успешно, один Linux worker пропущен по платформе.
- Переносимый Windows runner: 64 теста, успешно; исключения Linux перечислены в исходном runner, это не вся общая suite.
- GPIO preload собирается ARMhf с явным DT_NEEDED libdl; тест обёртки проверяет настоящее перенаправление чтения, флаги записи и остальные пути.
- Подсветка: сценарии micro/plum, listening/off/demo и возврат штатных триггеров в фикстурах sysfs.
- Worker в настоящем subprocess: обновление компонентов, откат после ошибки кандидата, сохранение выключенного режима и recovery_needed при неудачном восстановлении.
- Терминал PTY: три варианта предложения, корректное освобождение полноэкранного UI перед заменой процесса, обычная отмена без Traceback.

## Полный цикл готовых пакетов

Проверяются настоящие установщики и передача управления worker, а не только mock-функции: предыдущая тестовая версия -> текущая -> пакет с несовпадающей runtime-версией -> откат. Входы и профили в этих сценариях синтетические; SSH колонки не используется. Хеши контрольных файлов state сверяются после обоих этапов, неизвестный файл прежней программы сохраняется в резервной копии.

Linux запускается в bwrap с временной точкой монтирования поверх существующего home, без изменения HOME и без доступа к сети. Windows запускается в Wine с отдельными LOCALAPPDATA/ALISA_HOME. Это проверяет освобождение старого Python и замену app, но не заменяет настоящую Windows.

Журналы текущей ветки: `build/feature-*.log`; полные циклы: `build/linux-update-smoke/home/results.json` и `build/windows-update-smoke/results.json`. Они локальны и не включаются в релиз. Последующий Windows-прогон описан в [результатах проверки обновлений](windows-updates-validation.md).

## Что ещё требует проверки

- Новый updater на настоящей Windows: блокировки файлов, окно CLI и замена компонентов реальной колонки.
- Лайт 1 аппаратно в этой ветке, особенно программная кнопка микрофона в GPT.
- Windows 10, Chrome, Go, дополнительные подписки и длительные разговоры не следуют из одного прогона Windows 11/Edge.
- Потеря питания и недоступность SSH могут помешать полному восстановлению; результат recovery_needed сохраняет эту границу.
