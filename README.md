# Alisa Voice на Яндекс Станции Стрит (Mango)

Это форк проекта [Alisa-ChatGPT-voice-assistant](https://github.com/rison1337/Alisa-ChatGPT-voice-assistant)
(версия 0.3.11). Оригинал рассчитан на Лайт 1/2, Мини 2, Мини 3, Станцию 2 и Миди — на них обработка
звука (подавление эха и шумов, VQE) работает в `maind` на центральном процессоре. **Стрит устроена
иначе**, и здесь описано только то, чем этот форк от оригинала отличается.

Всё общее — установка, командная строка, обновления, VPN, подсветка, голосовые команды — здесь не
пересказывается: смотрите [README оригинала](https://github.com/rison1337/Alisa-ChatGPT-voice-assistant#readme)
и его каталог `docs/`.

---

## 1. Что такое Стрит (Mango)

Розничное название — **Яндекс Станция Стрит**, кодовое имя — **Mango**. Единственная портативная
колонка в семействе (со встроенным аккумулятором и зарядкой по USB-C) и единственная на 32-битном
процессоре.

Все значения ниже сняты с нашего экземпляра 26 ноября 2026 года по SSH под `root`, а не взяты из
документации.

| Параметр | Значение |
|---|---|
| Имя хоста | `Yandex-Station-Street` (суффикс серийного номера скрыт) |
| Плата | device-tree: `Yandex Station Mango DVT`, совместимость `amlogic,a1` |
| Процессор | 2 ядра ARMv7 rev 2 (Cortex-A35), `CPU architecture: 7`, расширения NEON, VFPv4, CRC32 |
| Разрядность | `armv7l`: и ядро, и все программы 32-битные, с аппаратной плавающей точкой |
| Ядро | Linux `5.15.137` |
| Оперативная память | `MemTotal: 226116 kB` — около 221 МиБ |
| Система | Buildroot (файл `/etc/os-release`), `quasar` версии `3.21` |
| Прошивка | `0.376.1.20.4861173338.20261116.100` (файл `/system/vendor/quasar/version_full`) |
| Аккумулятор | `battery`: 86 %, 8.12 В, состояние «разряжается» |
| Индикация | `mango:{red,green,blue,white}:logo0..2`, `mango:red:charge0..3`, `mango:charge:sync` |

### Разметка флеш-памяти (NAND поверх UBI)

| Раздел | Размер | Назначение |
|---|---|---|
| `mtd0 bootloader` | 2 МиБ | загрузчик |
| `mtd1 tpl` | 8 МиБ | первичный загрузчик |
| `mtd2 tee` | 1 МиБ | доверенная среда, `jffs2`, только чтение |
| `mtd3 recovery` | 50 МиБ | восстановление |
| `mtd4 boot` | 12 МиБ | ядро |
| `mtd5 system` | 80 МиБ | корневая система `ubi0:rootfs`, UBIFS, смонтирована **только для чтения** |
| `mtd6 bkupgrade` | 97 МиБ | `ubi1:bkupgrade`, UBIFS, **доступна запись** — сюда ставится порт |

Корень защищён от записи, поэтому все изменяемые файлы порта живут на `bkupgrade`, а правка `/etc`
требует временного перемонтирования корня в режим записи.

### Звук

| Что | Значение |
|---|---|
| Звуковая карта | `card0: AML-AUGESOUND` |
| `00-00` | `TDM-A-dummy` — заглушка, запись и воспроизведение |
| `00-01` | `TDM-B-acm8625` — усилитель ACM8625, воспроизведение и запись |
| `00-02` | `PDM` — микрофоны, только запись |
| `00-03` | `LOOPBACK-A` — петля для эхоподавления, только запись |
| Устройство вывода | `plughw:0,1` (в простое свободно), микшер `Master` |

Обработка голоса вынесена в отдельный сигнальный процессор **HiFi4 DSP** (устройство
`/dev/hifi4dsp0`), а не выполняется на центральном процессоре — из-за этого привычный способ
перехвата не работает, см. раздел 2.1.

### Кнопки, микрофон и питание

| Что | Как реализовано |
|---|---|
| Микрофон | кнопка `KEY_MUTE`, состояние выключения — переключатель `SW_MUTE_DEVICE` на `/dev/input/event0` (доступ `0660 root:input`) |
| Громкость, пауза, Bluetooth, Алиса | `adc_keypad`, `/dev/input/event3` |
| Сон | `maind` запускает `yandex-standby` и пишет `mem` в `/sys/power/state` |
| Автозапуск | загрузка в стиле Buildroot: выполняются только `/etc/init.d/S??*`; на устройстве уже есть `S95yandex-debugctl`, `S97quasar`, `S99alisa-port`, `S99streetssh` |
| SSH | `dropbear`, поднимается скриптом `S99streetssh`, см. раздел 5 |

Ограничение по памяти — практическое: 221 МиБ и 32-битное ядро означают, что 64-битные пакеты
(`aarch64`) здесь не запустятся, всё собирается под ARMhf.

## 2. Чем форк отличается от оригинала

| Область | Оригинал | Здесь (Стрит) |
|---|---|---|
| Перехват обработки голоса | подмена `YandexVqeC_GetOutputChannelData` в `maind` | подмена `YandexVqeC_DspClient_Process` в клиенте сигнального процессора |
| Выбор канала | по фиксированному номеру дорожки | по метке `(kind, index)`; обработанный канал — `vqe_0` = `(6, 0)` |
| Выключение микрофона | своя модель для каждой платы | `gpio_keypad` и `SW_MUTE_DEVICE`; при ошибке чтения считаем микрофон выключенным |
| Вывод звука | маршрут конкретной модели | штатный `speakers` → `dmix` → `hw:0,1` |
| Занятость звукового устройства | — | отдельный процесс `holder` первым открывает устройство, чтобы клиент не получал отказ `EACCES` на семафоре `dmix` |
| Автозапуск | штатные механизмы модели | `S99alisa-port` в `/etc/init.d` и `standby-inhibit.sh` |
| Голос и глубина рассуждений | по модели | 9 голосов (`voice`) и `reasoning` (`instant` / `high`) с откатом на прежнее значение |
| Сеть | VPN-сценарии оригинала | исходящее SSH-соединение (relay) для доступа к `chatgpt.com` |

### 2.1. Почему обычный перехват не работает

На Лайт 2 библиотека `vqe_tap.c` подменяет функцию-геттер и получает готовый канал. На Стрит
обработка идёт в сигнальном процессоре, геттер вообще не вызывается: библиотека загружается, но
счётчик попаданий остаётся нулевым. Поэтому файл
`engines/native/station/vqe_tap_mango_dsp.c` перехватывает вызов клиента процессора
(`libyandex_evil.so`) и выбирает обработанный канал по метке, а не по позиции в массиве из 16
дорожек. Всё остальное остаётся штатным: буферы, выключение микрофона и жизненный цикл процессора
не меняются — перехватчик лишь отправляет необязательные неблокирующие датаграммы через
`AF_UNIX`-сокет.

### 2.2. Зачем нужен внешний relay

`chatgpt.com` может отказать запросам напрямую с колонки. Клиент открывает **исходящее**
SSH-соединение к небольшому серверу, и HTTPS идёт через него. Сервер не расшифровывает трафик, не
имеет доступа к колонке и не принимает входящих подключений: канал односторонний —
«колонка → сервер → сайт». Без relay стек не запускается, и колонка остаётся обычной Алисой.

## 3. Что нужно до установки

1. **Root и SSH на колонке уже получены.** Порт трогает системные компоненты: подгружает библиотеку
   в `maind`, читает `/dev/input/event0`, пишет в `/etc/init.d`. Получение root в проект не входит и
   здесь не описано. Для доступа к устройству ввода подключайте группу `input` только процессу
   клиента (`setpriv --groups 29,104`) — не правьте `/etc/group`.
2. **Прошивка закреплена.** Нужна ровно `0.376.1.20.4861173338.20261116.100`. На другой сборке
   `stack.sh` не перехватывает управление и возвращает штатную Алису. Поддержки «любая Стрит на
   любой прошивке» нет.
3. **Один репозиторий ничего не устанавливает.** Нужны собранные под ARMhf `client.armhf`,
   `vqe_tap_mango_dsp.so`, `holder`, `dispatch`, `relay`, а также `native_agent.so` и `loopback.so`
   из установки оригинала, каталог `state/` с живой сессией и `MANIFEST` с контрольными суммами.
   `install.sh` — обновлятор поверх рабочей установки, а не первичный установщик.

## 4. Сборка

```sh
# 1. Перехватчик сигнального процессора
aarch64-linux-gnu-gcc -marm -mfloat-abi=hard -shared -fPIC -O2 \
  -o vqe_tap_mango_dsp.so engines/native/station/vqe_tap_mango_dsp.c -ldl

# 2. holder — нужны заголовки libasound под ARMhf
aarch64-linux-gnu-gcc -marm -mfloat-abi=hard -O2 -o holder deploy/street/holder.c -lasound

# 3. dispatch — язык Go, сборка под linux/arm
GOOS=linux GOARCH=arm GOARM=7 go build -o dispatch deploy/street/dispatch.go

# 4. клиент — тем же компилятором, что и оригинал, с правками этой ветки
```

Контрольные суммы проверяйте **на самой колонке**: побайтовой воспроизводимости кросс-сборок нет.

## 5. Постоянный доступ по SSH

Колонка не принимает входящих соединений из интернета, поэтому доступ идёт через домашний
сервер-посредник, который служит точкой входа в домашнюю сеть. Ключ колонки отличается от ключа
посредника, отпечаток хоста закреплён в отдельном файле `street-known_hosts` — это защита от
подмены, менять его вручную не нужно.

Настройка на рабочей машине описывается в файле `~/.ssh/config` отдельным блоком `Host street`:
адрес колонки в локальной сети, пользователь `root`, отдельный ключ с `IdentitiesOnly yes`,
закреплённый файл известных хостов и `ProxyCommand` через посредника. Конкретные адреса, имя
посредника и путь к файлу отпечатков в репозиторий не выносятся — они остаются в личной
документации.

После настройки работает просто `ssh street`. Скрипт `street-ssh.sh` из локального каталога с
отчётами о стенде делает то же самое без настройки и удобен для автоматизации.

Автозапуск SSH на колонке обеспечивает `/etc/init.d/S99streetssh` — он установлен и переживает
перезагрузку. При обновлении прошивки корень перезаписывается: скрипт нужно поставить заново.

## 6. Установка и проверка

Полная процедура — в файле [STREET.md](STREET.md): подготовка каталога на `bkupgrade`, `MANIFEST`,
`S99alisa-port`, `verify-post-power.sh`. Кратко:

1. Собрать компоненты, разложить в каталог на разделе с записью, сформировать `MANIFEST`.
2. Установить `S99alisa-port` в `/etc/init.d` при временно перемонтированном в запись корне.
3. Перезагрузить и проверить счётчики: `Process`, `layout_ok`, `eligible_blocks`,
   `vqe_0_datagrams`, `mute`, `phase`.

**Доказательство работы — только счётчики.** Загруженная библиотека в списке отображённой памяти,
строка `MANGO-NATIVE/1`, ответ HTTP 200 или открытый канал WebRTC сами по себе голосовой обмен не
подтверждают: датаграммы должны расти при открытом микрофоне и прекращаться при закрытом.

## 7. Ограничения

- Без доступного relay колонка возвращается к штатной Алисе.
- Сервер не сообщает, какая глубина рассуждений применилась (`effort_reported=unknown`): значение
  `high` подтверждается фактом приёма запроса и задержкой, а не полем в ответе.
- Обновление прошивки перезаписывает `/etc/init.d` — автозапуск придётся ставить заново.
- `stack.sh` при любой ошибке (relay, `holder`, клиент, `MANIFEST`, версия прошивки) отдаёт
  управление штатному загрузчику Алисы, а не оставляет колонку без голосового помощника.
